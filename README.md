# Atria Monitor

> 安卓设备实时监控 + AI 诊断的 KernelSU / SukiSU / Magisk / APatch 模块。
> 零依赖、秒级启动、WebUI 面板，用一个全新视角回答「我的设备现在到底在忙什么」。

---

## 一、创意来源

普通的系统监控工具回答的是「**现在各项指标是多少**」——CPU 47%、内存 67%、温度 38°C。
但真正困扰人的问题从来不是数字，而是：

- 「**为什么**我的设备用着用着就卡了？」
- 「**谁**在后台偷偷耗电发热？」
- 「**该不该**清内存？清了真的会变快吗？」
- 「这 60 KB/s 的网速，我明明没下载 anything 啊？」

数字本身不会回答这些问题，**解读数字才会**。Atria Monitor 的核心创意是：

> **采集交给本地规则引擎，解读交给 AI，人只看结论。**

具体来说，模块把三个通常割裂的东西缝成了一条链：

1. **一个 Native 采集器** —— 用 C 写、编译成 arm64 单文件二进制，4 秒一轮采 60+ 项指标，零解释器开销；
2. **一个本地规则引擎** —— 先于 AI 做趋势判断（「持续高位」还是「刚飙升」），告警/优化建议**不依赖网络**，断网也能跑；
3. **一个 AI 诊断层** —— 把采集结果结构化打包成 payload 喂给大模型（DeepSeek/OpenAI/通义/Kimi 等任选），输出「现象 → 元凶 → 建议 → 可执行动作」四段式诊断，并带**多轮追问**和**诊断记忆**。

这不是又一个「仪表盘」。它假设你不想盯曲线，只想听一句人话结论，并且这句结论最好能直接落地成一个动作。

## 二、主要功能

### 1. 实时监控（4 秒一轮，60+ 项指标）

| 维度 | 内容 |
|---|---|
| 内存 | 总量/已用/占比 + 趋势曲线 |
| CPU | 整体占用 + **每个进程**的 CPU%（实时波动值，非平均） |
| 温度 | 多区域传感器（CPU/GPU/充电芯片/modem…）取最大值 + 明细 |
| 电池 | 电量/充放电流/电压/温度 |
| 存储 | /data 占用 + 大文件目录扫描（du） |
| **网速** | wlan/rmnet 设备累计字节 → 差值算速率，**主数值带方向箭头（↑上传 / ↓下载）** |
| 后台进程 | 60 条按内存排序，PID/包名/状态/内存/CPU/图标，可勾选结束 |
| 内核压力 | PSI（CPU/内存/IO 压力）、交换、调度器信息、wakelock 耗电来源 |
| 模块状态 | 已装内核模块列表 + 启停开关 |

### 2. AI 诊断（模块的卖点）

- **四段式输出**：现象摘要 → 元凶定位 → 建议动作 → 可执行动作（kill 进程 / 清缓存 / 冻结应用）
- **6 种场景化模板**：通用 / 游戏卡顿 / 耗电快 / 内存不足 / 发热严重 / 开机慢，同一个设备状态在不同场景下给不同重点
- **诊断记忆**：历史诊断落盘 JSONL，下一轮诊断时把上一轮结果注入 prompt，AI 能说「比上次升了 8%」这种话
- **多轮追问**：诊断框里可以继续追问，保留对话上下文，不用每次从头说
- **本地规则引擎兜底**：`diagnoseLocal` 用最近 15 条历史算斜率，区分「持续高位」和「刚飙升」；没配 API key / 断网时自动走本地

### 3. 一键优化与安全护栏

- **一键优化**：AI 或本地规则给出动作清单，如结束后台进程、清缓存、冻结应用
- **KILL_GUARD 保护名单**：系统 UI、电话、启动器、输入法、宿主助手等关键进程**永远不会被 kill**，AI 误判也杀不掉
- **白名单机制**：`/data/adb/atria_whitelist.conf`（模块目录外，更新不丢失），候选列表图标自动从 APK 提取（native 图标提取器）

### 4. 面板工程细节

- **零依赖单文件 WebUI**：一个 `index.html`（HTML+CSS+JS 全内联），WebView 直接打开，无 Node/NPM/打包
- **双列进程表格**（CSS Grid `minmax(0,1fr)`）：长进程名不会把旁边一列挤没
- **历史趋势**：1h / 6h / 24h 可切换
- **告警历史**：温度/内存阈值告警落盘，可回看

## 三、使用方法

### 安装

1. 在内核管理器（KernelSU / SukiSU / Magisk / APatch）中刷入 `atria_monitor_vX.Y.Z.zip`
2. 重启设备
3. 打开 KsuWebUI（或任何「打开模块面板」入口），选择 **Atria Monitor**

> 不想重启也行：`service.sh` 只是拉起后台采集器，面板读的是 `/data/local/tmp/atria_status.json`，装完直接打开面板也能用（此时采集器是否在跑决定数据是否新鲜）。

### 配置 AI 诊断（可选但强烈建议）

面板右下角 **配置** 按钮：

| 字段 | 说明 |
|---|---|
| 平台 | DeepSeek / OpenAI / 通义千问 / Kimi / 硅基流动 / OpenRouter，或自定义 |
| API Key | 存到 `/data/adb/atria_ai.conf`（**模块目录外，更新模块不丢失**），仅供本机使用 |
| 模型 | 如 `deepseek-chat`；可点"自动获取"拉模型列表 |

**断网/无 key**：自动降级到本地规则引擎 `diagnoseLocal`，基础诊断和优化建议照常工作。

### 日常使用

1. **判断「卡不卡」**：看 CPU 趋势曲线 + 进程列表的 CPU% —— 高 CPU 低内存的进程会因按内存排序而被排到列表外，此时看 CPU% 列
2. **判断「为什么网速怪怪的」**：网速主数值有方向箭头 —— `↑ 84 KB/s` = 正在上传（常见于助手 API 上行），`↓ xx KB/s` = 正在下载；明细行 `wlan0 ↓x ↑y` 同时给两个方向
3. **跑一次诊断**：点「立即诊断」→ 选场景（游戏卡顿/耗电快/…）→ AI 输出四段式结论 → 在框里继续追问
4. **执行优化**：点「一键优化」→ AI/规则引擎生成动作清单 → 确认执行（受保护进程会被过滤）
5. **看趋势**：曲线区可切 1h / 6h / 24h

### 卸载

模块管理器里禁用/删除即可。配置文件（`atria_ai.conf` / `atria_whitelist.conf` / 历史记录）在 `/data/adb/` 下，需手动清理。

## 四、项目结构

```
├── module.prop             # 模块声明（id/name/version/versionCode）
├── customize.sh            # 安装脚本（权限设置）
├── service.sh              # 开机自起采集器
├── uninstall.sh            # 卸载清理
├── scripts/
│   ├── collect.sh          # 采集器（awk 解析 /proc、dumpsys、top 等）
│   ├── collect_loop.sh     # 采集循环（4s 一轮 + 历史落盘 + 注入链）
│   ├── atria_inject98.sh   # wakelock/存储注入
│   └── optimize.sh         # 优化动作执行（kill/缓存/冻结）+ 白名单读写
├── webroot/
│   ├── index.html          # WebUI 面板（单文件，零依赖）
│   └── module.prop         # KsuWebUI 面板入口声明
└── native/
    ├── collect.c           # 采集器源码（C）
    ├── collect_c_arm64     # 编译产物（arm64）
    ├── icon_extract.c      # APK 图标提取器源码
    └── icon_extract_c_arm64# 编译产物（arm64）
```

### 数据流向

```
service.sh (开机)
    └─> collect_loop.sh (4s/轮)
            ├─> native/collect_c_arm64      → /proc /sys dumpsys top
            ├─> scripts/collect.sh          → 解析聚合成 JSON
            ├─> scripts/atria_inject98.sh   → wakelock / du 存储注入
            └─> /data/local/tmp/atria_status.json   ← 面板 fetch
                                    └─> index.html 显示 + AI 诊断
```

**配置与数据文件**（模块目录外，更新模块不丢失）：

| 路径 | 内容 |
|---|---|
| `/data/adb/atria_ai.conf` | AI 配置（key/模型/平台） |
| `/data/adb/atria_whitelist.conf` | 保护白名单包名 |
| `/data/adb/atria_history.jsonl` | 历史趋势数据 |
| `/data/adb/atria_diag_history.jsonl` | AI 诊断记忆 |
| `/data/local/tmp/atria_status.json` | 最新一帧状态（只读快照） |
| `/data/local/tmp/atria_icons/` | 提取的 APK 图标缓存 |

## 五、设计与实现说明

### 为什么采集器用 C 而不是 shell

`/proc` 解析用 awk 写虽然能跑，但每轮 fork 一堆进程在低端设备上抖得厉害。
核心采集器用 C 写、静态编译成单文件 arm64 二进制，一次 fork 完成全量采集，内存占用 KB 级。
（源码 `native/collect.c`，编译产物 `collect_c_arm64` 已预编译，无需交叉编译环境。）

### 为什么是单文件 index.html

面板不分包、不打包、不依赖前端框架——整个 WebUI 就是一个 HTML。
代价是可维护性差一点（1900+ 行单文件），收益是**部署即改即用**：改完 `index.html` 推到设备，重新打开面板就是新的，没有构建步骤、没有 node_modules、没有版本依赖地狱。这在一个「只身一人、在平板上用 root 权限开发」的环境里是最鲁棒的选择。

### 为什么网速要带方向箭头

朴素实现把上下行求和成单一"网速"。但实测场景里设备常常是**持续上传 60-90 KB/s、下载近 0**（助手 API 上行）——用户没下载任何东西却看到 58 KB/s 的"网速"，会误判为采集错误。
v3.4.6 起主数值显示主导方向 + 箭头（`↑ 84 KB/s`），明细行同时给出双向。数据链本身经实测验证：面板计数器与内核 `/proc/net/dev` 逐字节相等。

### 为什么 AI 诊断要配本地规则引擎

AI 慢、贵、会断网。`diagnoseLocal` 用最近 15 条历史算斜率，判断「这个温度是持续高还是刚飙上来」——这种趋势判断本地做更快更稳，也作为无 key 时的兜底。
AI 的价值在**解读和组合推理**，不在算斜率。两者分工后，链路在断网时仍然完整可用。

### 为什么 kill 动作要有保护名单

AI 会幻觉。`KILL_GUARD`（前端）与 `PKG_PROTECTED`（后端 optimize.sh）对齐，系统 UI / 电话 / 启动器 / 输入法 / 宿主助手 / 面板进程本身**永远不会出现在可 kill 清单里**。模块面向其他用户分发，不能假设 AI 永远对。

### 历史教训促成的设计

- **JSON 括号平衡防护**：注入链曾因 `${DATA%?}` 剥括号但没补根 `}` 导致整个状态文件非法（面板每轮 fetch 都解析失败、回落重跑采集器）。现在每轮采样都做 `{`/`}` 平衡计数拦截。
- **exec 桥接只返回首行**：KernelSU/SukiSU 的 exec 桥接多行输出会被截断。读写一律走 base64 单行传输 + 前端解码。
- **WebView 内存回收**：面板数据全在 `lastNet`/`history`/`_r` 等闭包变量里，DOM 只做差异更新（`_r` 缓存上一次值，相同不重写），避免长开泄漏。

## 安装包下载
点击下载：[**atria_monitor_v3.5.8.zip**](https://github.com/lqx3617-dot/atria_monitor/releases/download/v3.5.8/atria_monitor_v3.5.8.zip)（1.4 MB，28 文件，SHA256 `e8c6f0e752204a047983cca1a94f9474ff4edc373fed7b61ba2db37230898c44`）

刷入方法：内核管理器（KernelSU / SukiSU / Magisk / APatch）选「模块」→ 「从存储安装」，选择下载的 zip，安装后重启即可用。面板打开方式：内核管理器里点本模块，或用任何 file:// 可访问的 WebView 打开「面板」。

七、注意事项

- **Root 必需**：模块依赖 KernelSU/SukiSU/Magisk/APatch 的 root 与模块机制
- **兼容性**：依赖 `/proc/net/dev`、`dumpsys`、`top -n 1 -b`、PSI（内核需开启 CONFIG_PSI，未开启时该项自动缺省）
- **隐私**：AI 诊断会把设备指标（不含个人文件内容）发给你配置的 API；不想发就别配 key，本地规则引擎完全够用
- **进程列表限制**：`top_processes` 60 条按 rss_mb 排序，CPU 高但内存小的进程可能排在列表外（历史遗留限制）——此时看 CPU% 列
- **温度误值**：临时传感器偶发尖峰（如读到 90°C 而同帧 battery 仅 32°C），判读以 battery.temperature 为准
